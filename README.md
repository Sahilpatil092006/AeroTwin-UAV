
# AeroTwin-UAV

**AI-Enabled Real-Time Digital Twin System for Health Monitoring, Fault Prediction and Mission Reliability of Aero Piston Engines in MALE UAVs**

---

> [!IMPORTANT]
> **Software-Only Prototype**: This project is a software-only research and demonstration platform. There is no physical engine or physical IoT hardware involved. All engine dynamics and sensor telemetry are synthesized through high-fidelity software simulations.

---

## 1. System Overview

**AeroTwin-UAV** is an end-to-end digital twin platform engineered to assess, monitor, and predict the real-time operational health, degradation, and mission reliability of aero piston engines deployed on Medium-Altitude Long-Endurance (MALE) Unmanned Aerial Vehicles (UAVs).

By pairing a physics-informed virtual engine model with machine learning pipelines, AeroTwin-UAV estimates physical states from noisy synthetic telemetry, detects anomalous operational patterns, predicts remaining useful life (RUL), and delivers risk-aware mission recommendations through an interactive 3D dashboard.

## 5. Directory Responsibilities

- **`frontend/`**: Hosts the complete operator cockpit and mission dashboard. Includes real-time sensor gauges, interactive 3D digital twin rendering with dynamic thermal/stress coloring, trendline telemetry plots, and a "What-If" scenario configuration panel.
- **`backend/`**: Encapsulates the virtual piston engine simulation, flight dynamics, digital twin state tracker, AI model inference, and real-time WebSocket communication server.
- **`data/`**: Manages generated telemetry time-series, historical flight profiles, and preprocessed datasets used to train predictive maintenance models.
- **`models/`**: Houses trained AI/ML model artifacts (e.g., Anomaly Detectors, Remaining Useful Life regressors, and Fault Classifiers) alongside serialization metadata and feature scalers.
- **`scripts/`**: Contains executable automation tools for bulk synthetic telemetry generation, batch model training, validation sweeps, and baseline benchmarks.
- **`notebooks/`**: Dedicated environment for exploratory data analysis (EDA), aerodynamic/thermodynamic formula verification, and rapid algorithm experimentation.
- **`docs/`**: Comprehensive system documentation, telemetry data dictionaries, mathematical formulations of engine thermodynamics, and user manuals.
- **`tests/`**: Automated test suite guaranteeing code correctness, numerical stability in simulation loops, API schema conformity, and WebSocket latency bounds.
- **`assets/`**: Repository for 3D model files (`.gltf` / `.glb`), engineering schematics, UAV liveries, and architectural diagrams.

## 6. Synthetic Data Strategy

> **Software-Only Prototype**: AeroTwin-UAV is an academic and research prototype without access to physical test cells or physical IoT sensor hardware. To train and validate our predictive maintenance and digital twin models, we utilize a physics-inspired numerical telemetry generator rather than claiming measured real-world flight test telemetry.

### Why Synthetic Data is Used
1. **Safety & Extreme Edge Case Coverage**: Physical UAV engine failures (such as catastrophic oil pump starvation or severe in-flight misfires) cannot be routinely induced on physical aircraft due to safety risks and hardware destruction costs.
2. **Deterministic Ground Truth**: Synthetic generation provides exact mathematical ground truth for Remaining Useful Life (`rul_hours`), component degradation states (`0.0` to `1.0`), and true anomaly labels.
3. **Piston-Engine Specific Dynamics**: Rather than adapting generic jet engine datasets (like NASA C-MAPSS), this generator simulates the specific thermodynamic and mechanical characteristics of 4-stroke turbocharged horizontally-opposed aero piston engines (Rotax 914/915 iS class).

### Telemetry Synthesis & Flight Regimes
Telemetry is synthesized across realistic mission flight profiles (`GROUND`, `TAKEOFF`, `CLIMB`, `CRUISE`, `DESCENT`, `LANDING`). Aerodynamic drag, atmospheric density altitude ($0 - 8,000$ m), and ambient temperatures (ISA lapse rate $-10^\circ\text{C}$ to $50^\circ\text{C}$) directly influence engine volumetric efficiency, thermal dissipation, and throttle demand.

### Fault Modes & Degradation Modeling
- **Gradual Degradation**: Component wear accumulates progressively across operational missions ($0.0 \rightarrow 0.25 \rightarrow 0.50 \rightarrow 0.75 \rightarrow 1.0$), driving progressive thermal elevation and mechanical drag.
- **Fault Classes**:
  - `NORMAL`: Nominal operation with Gaussian sensor noise.
  - `INJECTOR_ABNORMALITY`: Lean localized combustion, EGT spikes, fuel flow restriction, and RPM instability.
  - `COOLING_PROBLEM`: Heat dissipation loss, CHT exceeding redline thresholds, and oil temperature surges.
  - `LUBRICATION_PROBLEM`: Oil gallery pressure loss, thermal friction spikes, and elevated vibration.
  - `MISFIRE`: Cyclic torque loss, violent torsional vibration spikes ($8 - 22$ mm/s), and RPM jitter.
  - `SENSOR_ANOMALY`: Isolated electrical/transducer drift on a single channel with unaffected mechanical engine health, training AI models to differentiate instrumentation errors from true physical degradation.

### Anti-Leakage Partitioning Strategy
To prevent temporal data leakage, train/validation/test splitting is strictly partitioned by **`engine_id`**:
- **70% Engines** $\rightarrow$ `data/synthetic/train.csv` (35 virtual engines)
- **15% Engines** $\rightarrow$ `data/synthetic/validation.csv` (7 virtual engines)
- **15% Engines** $\rightarrow$ `data/synthetic/test.csv` (8 virtual engines)
No single engine's time-series samples ever span multiple partitions.

## 7. AI Remaining Useful Life (RUL) Prediction

A predictive prognostic regression model estimates the remaining operating hours (`rul_hours`) of the virtual aero piston engine before reaching critical degradation boundaries:

- **Model Type**: Random Forest Regressor (`RandomForestRegressor`, `n_estimators=200`, `max_depth=22`, `random_state=42`)
- **Target Variable**: `rul_hours` (continuous range $0.0 - 1000.0$ hours)
- **Input Features (13 Observable Telemetry Channels)**: `rpm`, `throttle`, `altitude`, `ambient_temperature`, `humidity`, `wind_speed`, `cht`, `egt`, `oil_pressure`, `oil_temperature`, `vibration`, `fuel_flow`, `engine_load`.
- **Target Leakage Prevention**: Ground-truth degradation columns (`engine_health`, `fault_type`, `fault_severity`, `anomaly_score`, `mission_risk`) are strictly excluded from input tensors.
- **Engine-Level Group Partitioning**: Mutually exclusive train (35 engines, 52,500 rows), validation (7 engines, 10,500 rows), and test (8 engines, 12,000 rows) partitions ensure zero engine leakage.
- **Evaluation Metrics (Direct from Model Evaluation)**:
  - **Validation Set**: MAE = $66.69\text{ hours}$, RMSE = $89.78\text{ hours}$, $R^2 = 0.9252$, Safe MAPE = $28.91\%$
  - **Unseen Test Set**: MAE = $66.85\text{ hours}$, RMSE = $88.41\text{ hours}$, $R^2 = 0.8996$, Safe MAPE = $24.27\%$
  - **Non-Negative Constraint**: All predictions pass non-negative clipping ($\hat{y} \ge 0.0\text{ hours}$).
- **Top Influential Telemetry Features**:
  1. `vibration` (Relative importance: 0.4532)
  2. `cht` (Relative importance: 0.2160)
  3. `oil_pressure` (Relative importance: 0.1176)
  4. `egt` (Relative importance: 0.0880)
  5. `fuel_flow` (Relative importance: 0.0624)
- **Model & Diagnostic Artifacts**:
  - Model Binary: `models/rul_model.joblib`
  - Model Metadata: `models/rul_model_metadata.json`
  - Actual vs Predicted Plot: `docs/figures/13_rul_actual_vs_predicted.png`
  - Error Distribution: `docs/figures/14_rul_error_distribution.png`
  - Degradation Relationships: `docs/figures/15_rul_degradation_relationship.png`
  - Feature Importance Ranking: `docs/figures/16_rul_feature_importance.png`

> [!WARNING]
> **Synthetic-Data Limitation & Prototype Disclaimer**:  
> The RUL model is trained and evaluated on physics-inspired synthetic aero piston engine telemetry generated for the AeroTwin-UAV software prototype. The RUL estimate is decision-support information for the prototype and is not certified for operational aviation use.
